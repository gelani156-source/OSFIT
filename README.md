# Stack 1.0 — версия для личного тестирования

Локальный финансовый PWA для iPhone, Android и компьютера. Русский интерфейс в стиле iOS, светлая/тёмная/системная тема. Без регистрации, внешних шрифтов, библиотек с CDN и трекеров. Работает на GitHub Pages, сборка не нужна.

## Загрузка на GitHub с телефона или компьютера

1. Распакуйте архив. Нужны **файлы внутри**, а не сам ZIP.
2. Создайте отдельный репозиторий, например `stack-finance`. Не заменяйте файлы другого приложения.
3. В браузере GitHub откройте репозиторий → **Add file → Upload files**. При необходимости включите полную версию сайта.
4. Загрузите файлы в корень репозитория. `index.html` должен находиться рядом с `app.js`, а не внутри дополнительной папки. Нажмите **Commit changes**.
5. Откройте **Settings → Pages**. В **Build and deployment** выберите **Deploy from a branch**. Ветка `main`, папка **/(root)** → **Save**.
6. Дождитесь успешной публикации. Откройте адрес, который покажет GitHub Pages. Если доступен переключатель **Enforce HTTPS**, включите его.
7. В Safari: **Поделиться → На экран Домой**. В Chrome Android: меню → **Установить приложение / Добавить на главный экран**.
8. Откройте Stack с иконки с интернетом. Дождитесь сообщения **«Готово к работе офлайн»**. После этого проверьте запуск в авиарежиме.

Минимально обязательные файлы:

```
index.html
app.js
domain.js
db.js
style.css
sw.js
manifest.webmanifest
icon.svg
icon-192.png
icon-512.png
```

README, LICENSE, example-import.csv, package.json и tests — документация, пример импорта и тесты. Их тоже можно загрузить. Ничего устанавливать через npm для работы приложения не требуется.

## Начало работы

Создайте первый счёт и укажите **фактический текущий остаток**. Затем задайте три бюджета на месяц. Старые операции, импортированные поверх текущего остатка, изменят его ещё раз: для импорта используйте остаток **до первой импортируемой операции**, либо отдельный счёт с подходящим начальным остатком.

Приложение запускается с пустыми счетами и операциями. Тестовые данные не включены.

## Что реализовано

- Счета: дебетовые, наличные, кредитные, накопительные; отрицательные остатки и архив. Балансы вычисляются из начального остатка и операций.
- RUB, USD, EUR. Курсы в рубли задаются вручную. Конвертация перевода — явная сумма списания и сумма зачисления.
- Доходы/расходы, заметка, дата, редактирование; удаление с отменой на 5,5 секунды. Точность до копеек.
- Оплата с нескольких счетов одной валюты: проверка общей суммы, кнопка «Поровну».
- Переводы между счетами исключены из доходов и расходов.
- Категории: создание, переименование, перенос в раздел и скрытие.
- Три месячных бюджета, лимит на сегодня и остаток дневного лимита.
- Свободный остаток: общий баланс минус резервы целей и неоплаченные регулярные платежи текущего месяца.
- История с выбором месяца, поиском, фильтром счёта и порционной загрузкой.
- Аналитика: доходы/расходы/сальдо, расходы по дням, категории, план/факт и текущие остатки счетов.
- Регулярные платежи: расписание, баннер, ручная отметка оплаты, защита от повторной оплаты одного месяца, .ics для календаря.
- Цели: резерв, пополнение и снятие. Резервы не изменяют баланс счетов.
- Долги: «мне должны»/«я должен», частичные возвраты; возврат создаёт операцию. Общий чек с долей одного друга создаёт долг одновременно с расходом.
- Шаблоны быстрых расходов: перед сохранением можно изменить данные.
- Разбор вставленного SMS / текста или содержимого фискального QR; подтверждение результата.
- Ссылки для системных Команд: текст находится после # и не попадает в HTTP-запрос.
- JSON-копия/восстановление, CSV-экспорт операций, CSV-импорт, проверяемый импорт Money Radar.
- PIN 4–6 цифр, соль + PBKDF2 SHA-256 (120 000 итераций), блокировка после скрытия и через 2 минуты бездействия.
- IndexedDB, атомарное сохранение, проверка версии при записи из нескольких вкладок. При конфликте обновите приложение.
- PWA-манифест, локальный Service Worker, все ресурсы в архиве.

## Формулы и правила

Лимит дня = (бюджет «Повседневные» − расходы этого раздела за прошлые дни текущего месяца) / оставшиеся дни месяца, включая сегодня. Округление вниз до копейки. На главной показан **остаток**: лимит дня минус сегодняшние повседневные расходы. Отрицательный остаток показывается как превышение.

Цели — виртуальный резерв в рублях, а не отдельный банковский счёт. Не записывайте резервирование ещё и расходом. Долги в свободный остаток не включаются. Уже переданный долг добавляется без движения денег; новое предоставление/получение денег внесите отдельной операцией. Возвраты отражаются в денежном потоке доходов/расходов. Это простой личный учёт, не бухгалтерский баланс активов и обязательств.

В текущем выпуске общий чек допускает одного должника. Сам чек учитывается целиком как расход, возврат — как доход. Чтобы изменить чек со связанным долгом, сначала удалите запись долга. Денежные операции не удаляются вместе с записью долга.

Короткие месяцы: платёж 29–31 числа переносится на последний доступный день. При начале нового месяца бюджеты нужно задать заново; неоплаченные платежи прошлого месяца видны в разделе платежей при выборе прошлого месяца. Главный баннер относится к текущему месяцу.

## Импорт

### Stack JSON

**Ещё → Импорт данных**. Выберите копию, проверьте число счетов и операций, подтвердите замену. Некорректный файл отвергается до записи; текущие данные сохраняются. JSON полностью заменяет базу, не объединяет её. Текущий PIN устройства сохраняется. PIN не включается в экспортируемую копию.

### Money Radar

Поддерживаются массивы `entries`, `transactions` или `operations` (в корне либо в `data`) с полями:

```json
{"entries":[{"date":"2026-10-30","type":"expense","amount":450.50,"category":"Кафе","note":"Кофе"}]}
```

Суммы Money Radar считаются рублями/основными единицами выбранной валюты, не копейками. Категории сопоставляются по имени; остальные получают выбранную категорию. Импортируются **операции**, не бюджеты, цели и долги старого приложения. Исходного кода и реального JSON Money Radar среди материалов не было; совместимость конкретного бэкапа надо проверить. Неизвестная структура останавливает импорт с сообщением. Нельзя обещать поддержку всех версий Money Radar.

### CSV

Смотрите `example-import.csv`. Кодировка UTF-8, разделитель `;` или `,`, кавычки и переносы внутри поля поддерживаются. Обязательны `date`/`дата`/`дата операции` и `amount`/`сумма`/`сумма операции`. Даты YYYY-MM-DD или DD.MM.YYYY. Десятичная точка либо запятая. Необязательны `type`/`тип` и `note`/`описание`/`назначение платежа`.

Тип — income/expense или доход/расход. Если type отсутствует, положительная сумма означает доход, отрицательная — расход. Проверьте знаки в своей выписке. Автоматическое распознавание любых выписок Сбера и других банков не заявлено. Экспорт CSV — отчёт со строкой на каждый сплит; он не предназначен для полного восстановления. Экспорт с переводами не импортируется этим простым импортёром: используйте JSON.

Импорт CSV/Money Radar добавляет записи на выбранный счёт. Совпадения по дате, типу, сумме, счёту и заметке пропускаются. Две реальные одинаковые покупки могут быть сочтены дублем — проверьте итог и добавьте недостающую вручную.

## Ссылки для Команд

В приложении есть пошаговая инструкция: **Ещё → Команды и умный ввод**.

```
https://ВАШ-АДРЕС/#text=URL_ENCODED_TEXT
https://ВАШ-АДРЕС/#add=1&amount=450.50&type=expense&note=Кофе
```

Используйте реальный адрес своего приложения вместе с папкой репозитория. Текст обязательно кодируйте действием «Кодировать URL». Не используйте параметры `?text=...`: такие параметры отправлялись бы хостингу. Stack использует `#text=...`, очищает фрагмент после открытия и не сохраняет операцию без подтверждения.

iOS может открыть ссылку в Safari с отдельным хранилищем, а не в установленном PWA. Если свои счета не видны, отмените ввод и вставьте текст внутри установленного Stack. Системная диктовка и сканирование выполняются средствами ОС; их сетевую приватность приложение не контролирует.

## Ограничения версии и отличия от большого ТЗ

Это самостоятельная реализация на **JavaScript ES modules + CSS + IndexedDB**, без React, Tailwind, Dexie, Zod и внешнего форка. Выбран готовый к загрузке вариант без сборки; доменная логика, хранилище и UI разделены. Десктоп использует двухколоночные карточки и ту же нижнюю навигацию, без бокового меню.

Нет синхронизации банков, аккаунтов, общего семейного пространства, фоновых Push, автодоступа к SMS, OCR фотографий чеков, камеры внутри приложения, встроенного распознавания голоса, Web Share Target, автоматических курсов ЦБ, истории курсов, вложений, тегов и Google Sheets. Содержимое QR вставляется вручную или через Команды; приложение не декодирует изображение QR. Курсы ручные, и **исторические отчёты пересчитываются по текущему заданному курсу**.

Напоминания в закрытом Stack приходят только из календаря, если вы импортировали .ics и календарь разрешает уведомления. Повторный импорт может создать дубли в некоторых календарях: удаляйте старый набор или используйте отдельный календарь Stack. Изменение платежа в Stack не меняет уже импортированное событие.

PIN скрывает интерфейс, **не шифрует IndexedDB и JSON**. Защита не рассчитана на человека с доступом к инструментам разработчика или файлам устройства. Утерянный PIN восстанавливается только через заранее сохранённую копию после сброса данных сайта. Не очищайте хранилище без копии.

Приложение не отправляет финансовые записи на сервер. Хостинг получает обычные запросы файлов приложения и может вести свои журналы посещений. Первый запуск и проверка обновлений требуют сети; после установки офлайн-кэша учёт работает без сети. Браузер может удалить локальные данные. Запрос постоянного хранения — просьба браузеру, не гарантия. Сохраняйте JSON регулярно.

## Обновление кода

1. Сохраните JSON-копию.
2. Замените файлы в том же репозитории и по тому же адресу.
3. При изменении кода увеличьте `VERSION` в `sw.js` (например, `stack-shell-v1.0.1`).
4. Откройте приложение с сетью. Новая версия загрузится в фоне.
5. Закройте все окна Stack (и Safari, если там открыт Stack), затем откройте снова. Новая версия активируется после закрытия старых вкладок. **Не очищайте данные сайта ради обновления.**

## Проверки разработчика

Node.js 20+; `npm test` (без npm install). Тесты проверяют копейки, сплиты, переводы, лимиты, короткие месяцы, платежи, парсеры, валидацию копий и офлайн-обработчик.

В этой среде проверены в Chromium первый запуск, сохранение счёта и бюджета, операции, перевод, сплит с долгом, аналитика и сохранение данных после перезапуска. Офлайн-обработчик проверяется автоматическим тестом. Реальный запуск установленного PWA в авиарежиме на iPhone/Android, календарные уведомления, PIN в HTTPS и восстановление конкретного Money Radar JSON требуют теста на устройстве. Это тестовая версия, не обещание полного аудита безопасности.

## Структура

- `domain.js` — суммы, баланс, бюджеты, импорт, валидация, календарь.
- `db.js` — атомарная запись и контроль версии IndexedDB.
- `app.js` — экраны, формы, обработчики, PIN, импорт/экспорт.
- `style.css` — адаптивный интерфейс.
- `sw.js` — офлайн-кэш, изолированный по пути приложения.
- `tests/` — воспроизводимые тесты.
